# Математическая постановка — КИВО 2026 v3

## 1. Объект оценки

Навигатор оценивает не сотрудника как такового, а потенциал научно-образовательного подразделения относительно конкретной проектной задачи.

Терминология: цифровой профиль сотрудника; компетенции; научные направления; индикаторы активности; роли и результаты; тематические кластеры; пересечения компетенций; потенциальные коллаборации; проектные команды; белые пятна; распределение нагрузки.

## 2. Цифровой след и доказательства компетенций

Пусть i — сотрудник, s — источник цифрового следа, k — компетенция.

x_is — наблюдаемая активность сотрудника в источнике s. Источники: публикации, гранты, ДПО, образование, учебная и проектная деятельность.

Для записи учитываются: нормированная интенсивность n(x_is), давность d_is, надёжность источника q_s и соответствие записи компетенции a_isk.

Вес доказательства: **w_is = n(x_is) · d_is · q_s**.

Индивидуальная сила компетенции: **C_ik = Σ_s w_is · a_isk**.

## 3. Онтология компетенций

Связка сущностей: **Цифровой след → Индикатор активности → Научное направление / область знания → Компетенция → Роль → Проектная задача → Результат.**

Компетенция имеет идентификатор, название, описание, область знания, тип, уровень экспертизы, связанные направления, роли и доказательства.

Между компетенциями задаются отношения: «часть», «связана с», «предпосылка для», «применяется в», «дополняет».

Матрица A=[a_isk] — вычислительное представление онтологии. Она переводит цифровые доказательства в вклад в компетенции. На прототипе матрица может быть экспертной и полуавтоматической; затем уточняться на размеченной выборке и с помощью NLP/LLM-классификации.

## 4. Профиль сотрудника

**p_ik = C_ik / max_k C_ik**, 0 ≤ p_ik ≤ 1.

Организационный вес сотрудника в базовой модели **не используется**: должность, статус или субъективная оценка полезности не должны искусственно увеличивать компетентность. Доступность и нагрузка учитываются отдельно как ограничения при формировании команды.

## 5. Профиль подразделения

Для подразделения D используем насыщаемую агрегацию:

**P_Dk = 1 − Π_{i∈D}(1 − p_ik).**

P_Dk ∈ [0,1] — коллективная обеспеченность компетенцией.

Дополнительно: **Depth_Dk=max_i p_ik** и число независимых носителей **N_Dk=#{i:p_ik≥τ}**.

## 6. Поиск компетенций для проекта

Проектная задача t задаётся вектором требований **g_t=(g_t1,...,g_tK)**, где g_tk∈[0,1].

Пользователь может выбрать компетенции из онтологии, указать требуемый уровень или ввести описание проекта текстом. Система предлагает набор компетенций из онтологии, после чего пользователь подтверждает или корректирует его.

Таким образом реализуется сценарий **«проект → требуемые компетенции → сотрудники/подразделение»**.

## 7. Покрытие проекта компетенциями

Для требуемой компетенции:

**Coverage_Dk(t)=min(P_Dk/g_tk,1)**, если g_tk>0.

Общее покрытие:

**Coverage(D,t)=Σ_k g_tk·Coverage_Dk(t) / Σ_k g_tk.**

0≤Coverage≤1. Значение 1 означает полное покрытие заданных требований.

Дефицит: **Gap_Dk(t)=max(g_tk−P_Dk,0)**. Компетенции с высоким Gap образуют «белые пятна» проекта.

## 8. Релевантность сотрудника и команды

**Fit(i,t)= (Σ_k p_ik g_tk)/(sqrt(Σ_k p_ik²)·sqrt(Σ_k g_tk²)).**

Это косинусная мера сходства двух векторов: насколько профиль сотрудника похож на требования проекта.

Для команды A: **P_Ak=1−Π_{i∈A}(1−p_ik)**, затем **TeamFit(A,t)=cos(P_A,g_t)**.

TeamFit — соответствие коллективного профиля команды требованиям проекта. В интерфейсе рекомендуется показывать «релевантность проекту» и «соответствие команды требованиям», не перегружая пользователя математическим термином.

## 9. Формирование проектной команды

Ищется A⊆D с требуемым покрытием, обязательными компетенциями, ограничением численности и доступной нагрузки.

**Score(A,t)=α·Coverage(A,t)+β·Interdisciplinarity(A)+γ·Novelty(A)−δ·Overload(A).**

Нагрузка и доступность — ограничения, а не коэффициенты компетентности.

## 10. Междисциплинарность

При π_c — доле участников команды из тематической области c:

**H(A)=−Σ_c π_c log π_c.**

Нормированная энтропия используется как показатель разнообразия областей знания.

## 11. Граф связей

G=(V,E), вершины — сотрудники. Вес связи:

**e_ij=λ1·sim_topics+λ2·coauthor+λ3·sim_teaching+λ4·sim_skills.**

Граф показывает существующие и потенциальные коллаборации и мосты между тематическими кластерами.

## 12. Устойчивость

**Resilience(D,t)=min_i Coverage(D\{i},t)/(Coverage(D,t)+ε).**

Показатель выявляет зависимость проектного покрытия от отдельных носителей компетенций.

## 13. Потенциал подразделения

**Pot(D)=(Breadth,Depth,Interdisciplinarity,Collaboration,Coverage,Resilience).**

Интегральный индекс возможен только как дополнительное представление. Для управления важнее профиль потенциала, покрытие конкретной задачи и белые пятна.

## 14. Ограничения

Модель предназначена для навигации по экспертизе, формирования проектных команд и поиска потенциальных коллабораций. Она не предназначена для автоматической аттестации, увольнения, оценки личности или определения «ценности» сотрудника. Демонстрационные данные синтетические.
