# Архитектура данных

Публичный репозиторий содержит только код, обезличенные/синтетические данные и документацию. Исходный raw-цифровой след и необезличенные персональные данные находятся во внутреннем защищённом контуре.

Слои данных:

1. **Raw** — исходные записи информационных систем.
2. **Normalized** — единый формат, нормализация и дедупликация.
3. **Evidence / Competency** — свидетельства активности и их сопоставление с КРМ.
4. **Analytics** — цифровые профили, профиль подразделения, проектные требования, покрытие и дефициты.
5. **Presentation** — демонстратор, dashboard, API и отчёты.

Минимальный provenance: `employee_hash`, `source_system`, `source_record_id`, `record_date`, `activity_type`, `raw_value`, `normalized_value`, `knowledge_domain`, `competency_id`, `evidence_weight`, `competency_level`, `mapping_version`.

JSON профиля является аналитической витриной, а не единственным хранилищем. При обновлении новые записи проходят дедупликацию и KRM mapping; пересчитываются только затронутые компетенции и агрегаты.

Для проектных запросов используется единый словарь `data/competency_ontology.json`. Это исключает появление в запросе компетенций, которых нет в утверждённом словаре КРМ.
