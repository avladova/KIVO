# Математическая модель

Сервис оценивает соответствие цифровых профилей сотрудников требованиям конкретного научно-образовательного проекта.

Для evidence `s` сотрудника `i`:

`w_is = norm(x_is) × q_s × d_is`

Для компетенции КРМ `k`:

`C_ik = Σ_s w_is × a_isk`

где `a_isk` — степень соответствия evidence дескриптору компетенции.

Нормированный профиль сотрудника:

`p_ik = C_ik / max_k(C_ik)`

Профиль подразделения:

`P_Dk = 1 − Π_i(1 − p_ik)`

Для проектного запроса `t` с требованиями `g_tk`:

`Coverage_Dk(t) = min(P_Dk / g_tk, 1)`

`Coverage(D,t) = Σ_k g_tk × Coverage_Dk(t) / Σ_k g_tk`

`Gap_Dk(t) = max(g_tk − P_Dk, 0)`

Для команды `A`:

`P_Ak = 1 − Π_i∈A(1 − p_ik)`

Косинусное сходство используется как дополнительная мера релевантности профиля проекту. Нагрузка не является множителем компетенции и учитывается отдельным ограничением:

`load_i + project_load_i ≤ capacity_i`

«Белые пятна» — компетенции, для которых `Gap_Dk(t) > 0`. В интерфейсе они показываются как требование, наличие, дефицит и возможный способ закрытия.

## Онтология

Проектный запрос и цифровой профиль используют единый словарь из `data/competency_ontology.json`. УДК относится к слою областей знаний и не заменяет словарь компетенций.
