# Получение и обновление цифровых профилей

Исходный цифровой след не превращается сразу в список компетенций. Целевой профиль содержит факты, нормализованные значения, evidence и производные уровни компетенций КРМ.

1. Extraction — извлечение текста, таблиц и метаданных.
2. Entity extraction — публикации, образование, ДПО, дисциплины, проекты, РИД и другие активности.
3. Normalization — единые даты, организации, типы активности и дедупликация.
4. Семантическое обогащение — научная область, тема, ключевые слова.
5. KRM mapping — сопоставление evidence с компетенциями КРМ; сохраняются similarity, confidence и mapping_version.
6. Evidence layer — source_id, raw_text, normalized_text, дата, competency_id и параметры соответствия.
7. Aggregation — расчёт уровня компетенции сотрудника.
8. Validation — эксперт подтверждает или исправляет критичные сопоставления.
9. Profile JSON — актуальная аналитическая витрина профиля.

## Конфиденциальность

Публичный репозиторий не должен содержать ФИО и другие необезличенные персональные данные. Raw-слой хранится во внутреннем защищённом контуре. В `data/` находятся только синтетические/обезличенные профили.

## Обновление

Новые или изменённые записи поступают через ETL/ELT, API/event или manual refresh. После дедупликации повторно сопоставляются только затронутые записи, пересчитываются связанные компетенции и версия профиля. Старые evidence сохраняются для аудита; давность учитывается коэффициентом `d_is`.

## Ввод в демонстраторе

Пользователь может добавить профиль вручную или импортировать JSON. Для проектного запроса компетенции выбираются из списка КРМ; свободный ввод идентификаторов компетенций не используется.
